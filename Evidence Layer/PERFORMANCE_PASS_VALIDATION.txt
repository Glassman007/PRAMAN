PRAMAN Evidence Graph — Dedicated Performance Pass Validation
============================================================

Scope
-----
Performance-only optimization. No matching, conflict, reconciliation,
authority, canonical-state, lineage, filter or cross-dashboard semantics were changed.

Implemented
-----------
1. Global cluster-level rendering remains the primary locality representation.
2. Stage projections are pruned by replay stage before rendering.
3. Locality replay frames and cumulative stage projections are memoized per data layer.
4. Adapter processing aggregation was changed from repeated array membership scans to
   source-level precomputation/reuse.
5. Source/adapter/normalization/matching/conflict/authority/canonical and filter models
   use memoized selectors where their inputs are immutable for the data-layer lifetime.
6. Parcel evidence/history projections are lazy: no parcel graph is created during
   locality browsing/autocomplete. A selected parcel is built once and cached.
7. Replay controller structural snapshots are cached by stage + filter state.
   Playback progress no longer rebuilds/filter-runs the evidence graph each tick.
8. Renderer performs incremental progress-only updates when graph structure is unchanged.
9. Renderer uses delegated node click handling.
10. Dense detailed graphs use viewport virtualization with overscan. The controller
    still owns the complete evidence snapshot; virtualization only limits live DOM/SVG nodes.
11. CSS containment is applied to graph surface, node and stage-column paint/layout units.
12. No force-layout worker or WebGL dependency was added because PRAMAN uses a fixed
    stage-column layout; virtualization addresses the relevant rendering scale directly.
